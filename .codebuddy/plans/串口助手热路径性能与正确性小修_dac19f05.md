## 用户需求
用户要求仔细审查串口助手项目并找出可优化之处。经确认，本次实施范围为「性能 + 正确性小修」共 7 项，不改变任何功能行为；明确不做端口列表差量刷新、异步导出、格式修复、csproj RID 调整，也不新增任何功能。

## 产品概述
对现有串口调试助手的接收显示与日志写入热路径做分配优化，并修正三处小的正确性问题。界面外观、操作流程、串口连接/收发/日志功能均保持不变。

## 核心改动
- HEX 格式化提速：消除逐字节字符串分配，高波特率 HEX 显示与发送日志显著降低 GC 压力，输出内容逐字符不变
- 文本解码提速：消除每包数据的中间字符数组分配，跨包多字节字符处理行为不变
- 显示刷新复用缓冲：消除每 75ms 一次的临时拼接对象分配
- 日志时间戳零分配：每行日志不再产生时间戳字符串，日志格式逐字符不变
- 丢弃计数修正：显示队列溢出时按真实字节数统计（原先按字符数，HEX 模式下虚高约 3 倍），状态栏「已丢弃 N 字节」更准确
- 断开误报消除：正常断开串口时，迟到的驱动错误事件不再误触发「串口通信异常」提示
- 注释修正：全局异常计数注释由「连续」改为「累计」，与实际行为一致（仅注释，不改逻辑）

## 视觉与行为效果
界面零变化；唯一可感知的差异是丢弃字节数更准确、正常断开时不再偶发误报错误提示。


## 技术栈
- 沿用现有栈：.NET 10 WPF（`net10.0-windows`，SDK 10.0.401）、CommunityToolkit.Mvvm 8.4.2、System.IO.Ports 10.0.11，**不新增任何依赖**
- 仅使用 BCL 既有 API：`string.Create<TState>` + `SpanAction`、`Decoder.GetChars(ReadOnlySpan<byte>, Span<char>, bool)` span 重载、`DateTimeOffset.TryFormat`、`StringBuilder.Append(ReadOnlySpan<char>)`、`stackalloc`，均无需新增 using

## 实现方案
全部为局部等价替换，不触碰三级有界 Channel 流水线、五态状态机、软/硬超时关闭链路的语义。7 项改动如下：

1. **FormatHex 查找表化**（`ViewModel/MainViewModel.cs` 第 654–665 行）：保留空数组返回 `string.Empty` 的前置判断；用 `string.Create(data.Length * 3 - 1, data, static (span, bytes) => ...)` 一次成型，回调内用常量 `"0123456789ABCDEF"` 按高低半字节索引填充，字节间单空格。输出必须与旧实现逐字符一致（大写、单空格分隔）。每包从 O(n) 次小字符串分配降为 1 次；921600 波特率下约每秒 9 万次分配归零。该方法同时服务 HEX 显示（第 460 行）与 TX 日志（第 301 行），两处同时受益。
2. **解码消除 char[] 中间分配**（第 470–472 行）：改为 `string.Create(charCount, (decoder: _utf8Decoder, data: message.Data), static (span, state) => state.decoder.GetChars(state.data, span, false))`。**严格保留** `GetCharCount(data, false)` → `GetChars(..., false)` 的调用顺序与 flush 参数，保证有状态解码行为不变；charCount 为 0 时 `string.Create` 直接返回 Empty，安全。回调同步执行于消费线程，不破坏「Decoder 只在消费线程使用」的历史约束；static lambda + 值元组状态无闭包分配。`_resetDecoderPending` 逻辑（第 464–468 行）不动。
3. **FlushDisplayAsync 复用 StringBuilder**（第 525–558 行）：把第 533 行的 `new StringBuilder()` 提到 while 循环外（初始容量 `MaxCharsPerFlush`），每轮开始 `Clear()`。单次 64KB 上限、`_displayGeneration` 校验、`Dispatcher.InvokeAsync(Background)` 一律不动。`ToString()` 产物不可变，复用安全。
4. **日志时间戳 stackalloc**（`Services/RealtimeLogService.cs` 第 308–315 行 `AppendLogLine`）：`Span<char> stamp = stackalloc char[23]`，`timestamp.ToLocalTime().TryFormat(stamp, out var written, "yyyy-MM-dd HH:mm:ss.fff")`，再 `_output.Append(stamp[..written])`。该格式恒为 23 字符，缓冲恰好足够。**不传 IFormatProvider**，与现状 `ToString(format)` 同用当前文化，避免异文化下行为漂移。其余拼接顺序不变。
5. **丢弃计数单位修正**（`ViewModel/MainViewModel.cs` 第 497–500 行）：显示队列 `TryWrite` 失败时把 `text.Length`（字符数）改为 `message.Data.Length`（字节数），与暂停路径（第 453、482 行）及状态栏「已丢弃 N 字节」文案口径一致。`message` 在 `await foreach` 作用域内可用。
6. **OnErrorReceived 在途护栏**（`Services/SerialPortService.cs` 第 314–315 行）：对齐 `OnDataReceived`（第 272–278 行）的写法——先 `sender is not SerialPort serial` 判断，再 `ReferenceEquals(serial, Volatile.Read(ref _serialPort))` 比对，不匹配直接 return，之后才 `BeginFaultHandling`。正常断开时 `CloseCoreAsync` 已先把 `_serialPort` 置 null，在途错误事件被挡掉；连接期间的真实错误不受影响。表达式体改为块体。
7. **注释修正**（`App.xaml.cs` 第 12 行）：「连续 UI 异常」改为「累计 UI 异常」，计数逻辑不动。

**性能与复杂度**：各处时间复杂度不变（O(n)），仅降低常数因子与 GC 压力；热路径每包/每行分配数分别降为 1 次字符串 / 0 次中间数组 / 0 次临时 StringBuilder / 0 次时间戳字符串。无新增锁、无新增线程、无 I/O 变化。

## 实施注意事项
- **输出等价是硬约束**：HEX 大写单空格、日志时间戳 23 字符当前文化、解码调用序列不变；探针验证须逐字符对比
- 服务层所有 `await` 保持 `ConfigureAwait(false)`；不改任何超时参数、队列容量、状态机 CAS 逻辑
- 勿动 `SerialPortService.cs` 第 55–56 行既存的 2 处 WHITESPACE 差异（本次范围不含格式修复）
